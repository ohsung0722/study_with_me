## 1. 무엇을, 왜 만드는가

**Studyverse**는 브라우저에서 접속하는 **3D 메타버스 독서실**이다.

유튜브의 "스터디윗미(Study with me)" 영상처럼, **혼자 공부하지만 누군가 옆에서 같이 공부하고 있다는 느낌**을 주는 것이 핵심이다. 누구나 가입 없이 들어와 아바타로 자리에 앉아 공부하고, 다른 사람들이 공부하는 모습과 공부 시간을 보며 동기부여를 받는다.

처음 아이디어는 "특정 방에 들어가면 그 방 사람끼리만 대화할 수 있게"였다. 대화(텍스트·음성)는 다음 단계로 미루지만, **공간을 구역(방) 단위로 나누고 서버가 누가 어느 구역에 있는지 아는 구조**는 첫 버전부터 만든다. 대화는 나중에 이 구역 단위 위에 얹는다.

## 2. 목표 · 비목표 · 반목표

**목표 (첫 버전)**
- 닉네임만 입력하고 바로 들어와 3D 독서실을 WASD로 걸어 다닐 수 있다.
- 열람실 자리에 앉으면 공부 타이머가 돌고, 다른 사람의 아바타·타이머가 실시간으로 보인다.
- 혼자 접속해도 공간이 비어 보이지 않는다 (NPC 메이트 + 실제 공부 기록).
- 라운지에서 쉬다가(음료, 소파, 배경음, 휴식 타이머) 다시 공부하러 돌아가고 싶어진다.
- 서버가 각 사용자의 현재 구역(라운지 / 열람실 / 스터디룸 A·B / 복도)을 판정한다.
- 사람끼리 서로 인사할 수 있다. 단 열람실 책상에 앉은 사람은 집중 모드로 인사를 받지 않는다.
- 내가 있는 공간이 또렷하고 다른 공간은 어둡게 보여서, 지금 어디에 있는지 자연스럽게 느낀다.

**비목표 (첫 버전에서 하지 않음 — 다음 단계)**
- 텍스트 채팅, 음성 대화, 캠
- 로그인 / 회원가입
- 휴대폰·태블릿 지원 (다음 단계에서 화면 조이스틱으로 지원)
- 라운지 2단계 기능: 다짐 포스트잇 벽, 같이 키우는 나무, 이모트(박수·하이파이브 등 — 인사는 첫 버전에 포함), 스트레칭 매트
- **자리 비움 감지**: 탭을 켜 둔 채 자리를 떠나는 경우는 고려하지 않는다 (사용자 결정). "아직 공부 중이세요?" 확인, 최대 세션 길이, 긴 세션 랭킹 제외 모두 하지 않는다. 앉아 있는 동안의 시간은 그대로 기록한다.

**반목표 (기술적으로 돌아가도 이렇게 되면 실패)**
- 공부를 방해하는 공간: 시끄러운 효과음, 잦은 알림, 열람실에서의 소음.
- NPC를 실제 사람인 척 속이는 것. NPC는 항상 "메이트"로 표시한다.
- 가입이나 설정을 강요해서 들어오기까지 오래 걸리는 것.
- 독서실 탭을 뒤로 숨기고 다른 창에서 공부할 때 타이머가 멈추거나 "접속 끊김"이 되는 것.

## 3. 제약

- **플랫폼**: PC 데스크톱 브라우저 (최신 Chrome / Edge / Firefox, WebGL2). 휴대폰으로 접속하면 "PC에서 접속해 주세요" 안내.
- **규모**: 동시 접속 약 10명으로 시작. 이 구조로 수백 명까지 서버 한 대로 감당하는 것을 전제로 설계한다 (1,000명 이상은 서버 여러 대 + Redis 어댑터로 확장, 지금은 하지 않음).
- **공간 정원**: 건물 한 채에 30~50명. 그 이상은 나중에 건물을 여러 채(채널)로 나누는 방식으로 늘린다. 첫 버전은 건물 한 채.
- **비용**: 저렴한 서버 한 대로 운영 가능해야 한다.
- **개발 환경**: Windows 11, 작업 폴더 `C:\Users\ASUS\OneDrive\Desktop\studyverse` (OneDrive 동기화 폴더). 아직 git 저장소가 아니다.

## 4. 만드는 방법 (Approaches)

세 가지를 검토했고 **1번을 선택했다.**

| | 방식 | 장점 | 단점 |
|---|---|---|---|
| **1 (선택)** | three.js 직접 + Node.js/Socket.IO 서버 + SQLite | 구조가 단순하고 문제 추적이 쉬움. Socket.IO의 room이 구역 단위 대화와 그대로 맞음. 서버가 타이머·구역·NPC를 맡기 쉬움 | UI가 많은 기능(포스트잇 등)은 직접 만들 게 많음 |
| 2 | React Three Fiber + Colyseus | UI 만들기 편함, 상태 동기화·방 매칭·수평 확장 기본 제공 | 배울 층이 많고 10~수백 명 규모엔 과함. 수천 명을 처음부터 노릴 때 유리 |
| 3 | 서버 없이 Supabase Realtime만 | 서버 운영 불필요 | 서버가 공부 시간을 세야 한다는 결정과 충돌 (숨긴 탭은 브라우저가 멈춤), NPC 구동도 어려움 → 탈락 |

**선택 이유**: 현재 규모(10명 → 수백 명)와 기능에 가장 단순하게 맞고, "서버가 시간을 센다"는 결정과 구역 단위 대화 확장에 자연스럽게 맞는다.

## 5. 결정된 내용

### 5.1 공간 배치 (시안: `lounge-layout.html`)

건물 한 층. 위에서 본 배치:

```
┌──────────────┬────┬──────────────┐
│              │    │ 📚 열람실 (조용) │  ← 입구에서 가장 안쪽
│  ☕ 라운지     │ 복 ├──────────────┤
│  (큰 공간)    │ 도 │ 🚪 스터디룸 A  │
│              │    ├──────────────┤
│              │    │ 🚪 스터디룸 B  │
└──────────────┴────┴──────────────┘
                ⬆ 입구
```

- **가운데 복도**가 입구에서 안쪽으로 길게 뻗는다.
- **왼쪽: 큰 라운지** (휴식 공간, 나중에 채팅이 붙으면 자유 대화 구역).
- **오른쪽 안쪽: 열람실** — 칸막이 책상 20~24석, 조용한 구역.
- **오른쪽 입구 쪽: 스터디룸 A, B** — 각 4~6명, 유리문(밖에서 안이 보임). 나중에 방 단위 대화가 붙는 곳.
- 각 구역은 복도 쪽으로 문이 있다.

**실제 크기** (*설계자 판단* — 시안은 한 화면에 담으려고 크게 줄인 것). 1단위 = 1m, 아바타 키 약 1.2m 기준:

| 공간 | 대략 크기 | 비고 |
|---|---|---|
| 건물 전체 | 약 36m × 24m | v1.1에서 32m → 36m (열람실·스터디룸 쪽을 넓힘) |
| 복도 | 폭 3m | 두 사람이 엇갈려 지나갈 수 있는 폭 |
| 라운지 | 약 13m × 24m | 커피머신·자판기·소파·기록판·라디오·창가가 여유 있게 놓이는 크기. v1.1: 책장, 소파 사이 커피테이블과 큰 러그, 창가 바 테이블, 큰 화분, 라디오 옆 독서 코너 |
| 열람실 | 약 20m × 14m | 칸막이 책상 24석, 3m 간격(책상 사이 1.4m, 의자 뒤 통로 약 1.4m) + 복도 쪽 통로 약 2m |
| 스터디룸 A·B | 각 약 20m × 5m | 6인 테이블 (오른쪽 폭을 그대로 씀) |

- 기준: 걷는 속도 약 4m/s일 때 **입구에서 열람실 가장 안쪽 자리까지 10초 안**. 너무 넓으면 걸어 다니기 지루하고, 너무 좁으면 답답하다.
- 시안은 안을 보여주려고 벽을 낮게 잘랐지만, 실제 벽은 **천장까지 올라간다**. 3인칭 카메라가 벽에 막히면 카메라를 캐릭터 쪽으로 당긴다. 다른 공간은 문과 유리벽(스터디룸)으로 보인다.

### 5.2 분위기 · 시간대 (시안: `space-mood.html`, `day-night.html`)

- **낮 = A "따뜻한 원목 독서실"(원래 밝기)**: 나무 책상, 노란 스탠드 불빛, 아늑한 느낌.
- **밤 = C "로파이 열람실"**: 어두운 방, 책상 스탠드만 켜짐, 창밖에 비와 달.
- **전환 기준**: 각 사용자 PC의 현지 시각. 07:00~19:00 낮, 19:00~07:00 밤. 전환 시 약 1.6초에 걸쳐 색·조명이 부드럽게 바뀐다.
- 시안의 색상 값(`space-mood.html`의 `THEMES.warm`, `THEMES.night`)을 출발점으로 쓴다.

### 5.3 아바타 (시안: `avatar-rounded.html`)

- **둥근 2등신 캐릭터**: 큰 둥근 머리, 둥근 몸통, 캡슐형 팔다리, 공 모양 손발, 볼터치, 작은 입. 각진 면 없음.
- **코드로 직접 생성**(외부 3D 모델 파일 없음). 걷기·앉기·마시기 동작도 코드로 움직인다. 나중에 glTF 모델로 교체할 수 있게 아바타 생성부를 한 곳에 모은다.
- **꾸미기**: 머리 모양 3종(짧은 머리 / 긴 머리 / 똥머리) + 머리 색 + 옷 색.
- 머리 위에 **이름표 + 상태**(공부 타이머 `01:12:40` / `휴식 05:12` / 이름만) 표시.

### 5.4 입장

1. 첫 화면에서 닉네임 입력(2~12자, 기본 비속어 필터 — *설계자 판단*), 머리 모양·머리 색·옷 색 선택.
2. 브라우저(localStorage)에 **익명 ID**를 만들어 저장. 같은 브라우저로 다시 오면 닉네임·꾸미기·기록이 이어진다. 다른 브라우저/PC에서는 새로 시작 (나중에 로그인이 생기면 이어받기).
3. 입구에서 시작.

**정원이 찼을 때** (*설계자 판단* — 지금 10명 규모에선 드문 상황):
- 자리가 모두 찼어도 입장은 된다. 라운지·복도를 다니며 쉴 수 있고, 빈 자리가 나면 앉는다.
- 건물 전체 정원(기본 50명)을 넘으면 "지금 독서실이 가득 찼어요" 화면을 띄우고 자리가 나면 자동 입장.
- 건물 여러 채(채널)는 첫 버전에서 만들지 않지만, 데이터 구조(세션 기록·구역 room 이름)에 **건물 ID**를 미리 넣어 나중에 늘리기 쉽게 한다.

**같은 사람이 탭 두 개를 연 경우** (*설계자 판단*): 같은 익명 ID로 새 탭이 접속하면 이전 탭은 "다른 탭에서 접속했어요"로 연결을 끊는다.

### 5.5 이동 · 조작

- **WASD 이동 + 마우스로 카메라 회전**, 3인칭 카메라가 캐릭터 뒤를 따라간다.
- 벽·책상·가구는 통과하지 못한다.
- **E = 상호작용** (가까이 가면 화면에 "E 앉기", "E 커피 마시기" 같은 안내가 뜬다).
- PC 전용. 다음 단계에서 휴대폰 화면 조이스틱 추가.

### 5.6 앉기 · 공부 타이머

- 열람실(그리고 스터디룸) 빈 자리 근처에서 E → 앉기. **앉으면 공부 타이머 자동 시작**, 카메라는 책상이 보이는 고정 시점으로 바뀐다.
- E를 다시 누르거나 이동 키를 누르면 일어나고 타이머가 멈춘다.
- **시간은 서버가 센다.** 클라이언트는 표시만 한다. 탭을 숨겨도 계속 올라간다.
- 접속이 끊기면 자동으로 멈추고 그 자리는 비워진다.
- 앉은 공부 시간 한 구간(앉음 → 일어남/끊김)을 하나의 **공부 세션**으로 저장한다.

### 5.6.1 인사 상호작용 (시안: `focus-dim.html`)

- 다른 사람 가까이(약 2m 안)에서 **E → 인사하기**. 여러 명이 가까우면 가장 가까운 사람에게 간다(*설계자 판단*).
- 내 캐릭터가 손을 흔들고 머리 위에 👋가 뜬다. 주변 사람 모두에게 보인다.
- 상대 화면에 "OO님이 인사했어요 👋 **[인사 받기]**"가 약 5초 뜬다. 상대가 받으면(버튼 또는 E) 상대 캐릭터도 손을 흔든다. 무시하면 그냥 사라진다.
- 인사는 **5초에 한 번** 보낼 수 있다(보내는 사람 기준, 도배 방지 — 사용자 결정).
- **집중 모드인 사람에게는 인사할 수 없다.** 가까이 가도 "E 인사하기" 대신 "🔒 집중 중"이 표시된다. 서버도 집중 모드 사용자에게 가는 인사를 거절한다.
- 집중 모드 중에는 나도 인사를 보낼 수 없다.

### 5.6.2 집중 모드 (프라이빗 모드)

- **열람실 책상에 앉으면 자동으로 켜지고, 일어나면 꺼진다.** 스터디룸 의자와 라운지 소파에 앉을 때는 켜지지 않는다(*설계자 판단*: 스터디룸은 나중에 대화하는 곳).
- 효과:
  - 다른 사람의 인사(및 이후 추가될 상호작용)를 받지 않는다.
  - 머리 위 이름표에 🔒 표시.
  - **화면이 살짝 어두워지고 내 자리 주변만 밝게** 보인다(화면 가장자리가 어두워지는 효과).
- 다른 사람들의 아바타와 공부 타이머는 어두운 화면에서도 계속 보인다. "같이 공부하는 느낌"이 핵심이므로 완전히 가리지 않는다.

### 5.6.3 공간별 어둡게

- **내가 있는 구역만 원래 밝기, 다른 구역은 어둡게** 그린다. 기본값은 원래 밝기의 약 45%이고, 시안의 슬라이더로 정한 값을 출발점으로 빌더가 조정한다.
- **복도에 있을 때는 전체가 원래 밝기**다(지나다니는 통로이므로, *설계자 판단*).
- 구역이 바뀌면 약 0.5초에 걸쳐 부드럽게 전환된다.
- 다른 구역 사람들의 이름표도 함께 살짝 흐려진다.
- 클라이언트에서만 처리하는 시각 효과다. 서버는 관여하지 않는다.
- 낮/밤 전환(5.2)과 겹쳐 적용된다.

### 5.7 구역 판정 (대화 확장의 기반)

- 구역: `lounge`, `corridor`, `reading`, `studyA`, `studyB`.
- 서버가 각 사용자의 위치로 현재 구역을 판정하고, 바뀌면 Socket.IO room을 옮긴다(`join`/`leave`).
- 첫 버전에서는 화면 구석에 "📍 스터디룸 A" 같은 현재 위치 표시에만 쓴다.
- 다음 단계의 채팅은 "같은 room에만 메시지 전달"로 얹는다. 열람실은 대화 불가 구역으로 둔다.

### 5.8 NPC 메이트

- **실제 접속자가 3명 미만일 때** 메이트 2~3명이 열람실 자리에 앉아 공부하고 있다.
- 실제 사람이 늘면 메이트가 하나씩 일어나 걸어 나간다(사라짐).
- 메이트는 항상 **보라색 "메이트" 이름표**를 단다. 메이트의 공부 시간은 기록·랭킹에 포함하지 않는다.
- 메이트는 서버가 관리해서 모든 사람에게 같은 메이트가 같은 자리에 보인다.

### 5.9 공부 기록

- 저장소: 서버의 **SQLite** 파일.
- 저장 단위: 공부 세션(익명 ID, 닉네임, 자리, 시작·끝 시각).
- **"오늘"의 기준: 한국 시간(Asia/Seoul) 자정.** 자정을 넘는 세션은 기록상 자정에서 둘로 나눠 각 날짜에 반영한다 (*설계자 판단*).
- **관리 도구** (*설계자 판단*): 서버에서 실행하는 간단한 관리 명령(관리자 키 필요)으로 특정 닉네임 숨기기·변경, 특정 기록 삭제가 가능하게 한다. 공개 기록판에 부적절한 닉네임이 올라왔을 때 DB 파일을 직접 고치지 않기 위함.
- 보여주는 곳:
  - 라운지 **오늘의 기록판**: "오늘 N명 · 총 H시간", 오늘 오래 공부한 사람 TOP 5 (닉네임 + 시간).
  - 열람실 각 자리: 가까이 가면 "오늘 이 자리에서 3시간 공부했어요".
  - 내 기록: 오늘 내 누적 공부 시간 (화면 HUD).

### 5.10 라운지 (첫 버전)

| 요소 | 동작 |

| ☕ 커피머신 · 🥤 자판기 | E → 음료 선택(예: 아메리카노, 라떼, 녹차, 이온음료) → 손에 컵을 들고 다니며 가끔 마시는 동작. 자리에 앉으면 책상 위에 컵이 놓인다. 다른 사람에게도 보인다. 다른 음료를 고르거나 일정 시간이 지나면 사라진다. 순수 재미 요소(능력치 없음). |

## 6. 구조 개요

```
studyverse/
├─ client/   Vite + TypeScript + three.js, 화면 UI는 HTML/CSS 오버레이
├─ server/   Node.js + TypeScript + Socket.IO, SQLite
└─ shared/   양쪽이 함께 쓰는 것: 메시지 타입, 맵 데이터(구역·자리·충돌 박스·상호작용 지점)
```

- **맵은 코드(데이터)로 정의**한다. 구역 경계, 자리 위치, 벽/가구 충돌 박스, 상호작용 지점을 `shared`에 두어 클라이언트(그리기·충돌)와 서버(구역 판정·검증)가 같은 데이터를 쓴다.
- **움직임 동기화**: 내 캐릭터는 클라이언트가 바로 움직이고, 위치를 초당 약 10회 서버로 보낸다. 서버는 움직이는 사람의 위치만 모아 초당 약 10회 한꺼번에 내려보낸다(앉아 있는 사람은 보내지 않음). 다른 사람 캐릭터는 받은 위치 사이를 부드럽게 보간해 그린다.
- **서버가 결정하는 것**: 구역, 자리 점유(한 자리에 한 명), 공부 타이머, 집중 모드 여부, 인사 전달(거리·집중 모드·5초 제한 확인), NPC 메이트, 기록.
- 하나의 Node 서버가 클라이언트 정적 파일과 Socket.IO를 함께 제공한다.
- **나중의 확장을 위한 분리** (*설계자 판단*): 게임 로직(구역 판정, 자리, 타이머, NPC, 기록)은 통신 방식(Socket.IO)과 분리된 모듈로 둔다. 메시지는 Socket.IO 전용 기능에 기대지 않는 단순한 JSON 형식으로 정의한다. 이렇게 하면 서버 확장 시 Cloudflare를 앞단에 두는 것은 설정만으로 가능하고, 필요하면 Cloudflare Workers/Durable Objects(건물 1채 = 객체 1개) 같은 다른 실행 환경으로 옮길 때도 통신 계층만 바꾸면 된다.
